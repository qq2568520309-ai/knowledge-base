## 一、语言基础

???+ question "1. C 和 C++ 有什么区别？"
    C 是面向过程的语言，C++ 在其基础上增加了类、模板、异常、引用、命名空间和 RAII，是多重范式语言。
    底层差异：C++ 有名字修饰（name mangling）与函数重载，`void*` 不能隐式转成其他指针，必须显式转换。
    资源管理：C 用 `malloc/free` 手工管理，C++ 用构造/析构 + 智能指针把释放绑定到生命周期上。

???+ question "2. C++ 有哪些特点？"
    封装、继承、多态之外，还有模板泛型、RAII、运算符重载、异常、STL 与零开销抽象（zero-cost abstraction）。
    「零开销」指不用的特性不付费、用了的手写代码不会更好；代价是编译慢、ABI 复杂、UB 多，需要程序员自己守规则。

???+ question "3. 值传递、引用传递、指针传递有什么区别？"
    值传递拷贝一份实参，函数内修改不影响外部，大对象有拷贝开销；指针传递拷贝的是地址，可修改指向对象，但需要判空。
    引用传递是实参的别名，不产生拷贝，函数内修改直接作用于原对象，且不能为空、不能改绑。
    C++ 惯例：内置类型按值，大对象用 `const T&` 只读、`T&` 输出，需要「可空」语义时才用指针。

???+ question "4. 重载、重写、隐藏（overload / override / hiding）有什么区别？"
    重载：同一作用域内同名不同参数，编译期按实参选版本，与返回值无关。
    重写：派生类用相同签名覆盖基类 `virtual` 函数，运行期经 vtable 分发，签名必须完全一致（协变返回除外）。
    隐藏：派生类出现同名函数就隐藏基类所有同名重载（不论参数），要用 `using Base::f;` 才能重新引入。

    !!! warning "易错"
        基类 `f(int)` 非虚、派生类写 `f(double)` 是隐藏不是重载；`d.f(1)` 可能悄悄走派生版本。

???+ question "5. struct 和 class 有什么区别？"
    默认访问权限：`struct` 成员和继承默认 `public`，`class` 默认 `private`，这是唯一的标准差异。
    两者都能有构造函数、虚函数、静态成员、模板，也能互相继承；C++ 里 `struct` 常用来表示纯数据聚合。
    面试常顺带问：C 的 struct 不能有成员函数，C++ 的可以。

???+ question "6. 四种 cast 分别怎么用？"
    | 转换 | 检查时机 | 典型用途 |
    | --- | --- | --- |
    | `static_cast` | 编译期 | 数值转换、`void*` 还原、有继承关系的上行/下行（下行不检查） |
    | `dynamic_cast` | 运行期 | 多态类型的向下/交叉转换，失败返回 `nullptr`，引用则抛 `bad_cast` |
    | `const_cast` | 编译期 | 去掉/加上 `const`、`volatile`，仅此一种能力 |
    | `reinterpret_cast` | 编译期 | 重新解释二进制位，指针与整数互转，最危险 |

    C 风格 `(T)x` 会按 `const_cast → static_cast → reinterpret_cast` 顺序尝试，难以 grep，C++ 中应避免。

???+ question "7. extern \"C\" 的作用是什么？"
    让被修饰的函数/变量按 C 的规则进行名字修饰和链接，从而能被 C 代码调用，或调用已有的 C 库。
    典型写法：`#ifdef __cplusplus extern "C" { #endif` 包住头文件声明。
    注意它只影响链接名，不影响调用约定；被 `extern "C"` 的函数不能重载。

???+ question "8. static 关键字有哪些用法？"
    局部变量：生命周期延长到程序结束，存于静态区，C++11 起初始化线程安全（guard variable）。
    全局/命名空间作用域：内部链接，仅本翻译单元可见；函数同理。
    类成员：静态数据成员属于类、需类外定义（C++17 可 `inline static` 类内定义）；静态成员函数没有 `this`。

???+ question "9. const 关键字有哪些用法？"
    修饰变量表示只读；修饰引用/指针表示不能经它修改；修饰成员函数表示不修改对象状态，且能被 const 对象调用。
    修饰返回值可阻止 `(a = b) = c` 这类误用；`const T&` 形参能绑定临时对象并延长其生命周期；编译期可求值的 const 整数可作数组大小。

???+ question "10. volatile 的作用是什么？能用来做线程同步吗？"
    告诉编译器该对象可能被程序之外的因素改变，每次访问都必须真正读写内存，不得缓存到寄存器或删除「无用」读写。
    适用场景：内存映射 I/O 寄存器、信号处理函数里与 `sig_atomic_t` 配合的变量。
    它不保证原子性、不建立 happens-before、不阻止 CPU 重排，所以不能替代 `std::atomic` 做线程同步。

## 二、指针与内存

???+ question "11. 指针和引用有什么区别？"
    引用必须初始化、不能改绑、没有空引用、没有引用的引用，`sizeof` 得到被引用对象大小；指针可以为空、可改指向、可多级。
    引用不是对象，不保证占用独立存储；底层通常用地址实现，但语言层面它是别名。
    因此「引用更安全」只体现在不能为空和不可改绑，生命周期问题依旧存在。

???+ question "12. 野指针和悬空指针有什么区别？怎么避免？"
    野指针（wild pointer）是未初始化的指针，指向随机地址；悬空指针（dangling pointer）指向已被释放或已失效的对象。
    两者解引用都是未定义行为，可能崩溃也可能「看起来正常」，最难排查。
    规避：定义即初始化 `nullptr`、`delete` 后立即置空、优先用 `unique_ptr/shared_ptr`、注意返回局部变量地址。

???+ question "13. new/delete 和 malloc/free 有什么区别？能混用吗？"
    `new` 是运算符：分配内存 + 调用构造函数，返回类型化指针，失败抛 `std::bad_alloc`，可以重载。
    `malloc` 是库函数：只分配字节，返回 `void*`，失败返回 `NULL`，需要自己算大小并 `free`。
    不能混用：`new` 的内存用 `free` 不会调析构，`malloc` 的内存用 `delete` 会调不存在的析构，都是 UB。

???+ question "14. new[] 和 delete[] 为什么必须配对？"
    `new[]` 对每个元素调用构造，并为「析构非平凡」的类型额外分配 cookie 记录元素个数（实现相关）。
    `delete[]` 读出个数后逆序析构再释放整块；用 `delete` 释放 `new[]` 只析构首个元素并可能释放错地址。
    现代写法直接 `std::vector<T>` 或 `std::unique_ptr<T[]>`，从根上避免配对问题。

???+ question "15. C++ 程序的内存分区是怎样的？"
    栈：局部变量、函数参数、返回地址，自动分配释放，向下增长。
    堆：`new/malloc` 申请，向上增长，由分配器和程序员管理。
    全局/静态区：`.data` 存已初始化全局与静态变量，`.bss` 存零初始化；常量区存字符串字面量与只读常量；代码区存指令，只读。

???+ question "16. 堆和栈有什么区别？"
    | 维度 | 栈 | 堆 |
    | --- | --- | --- |
    | 管理方 | 编译器自动 | 程序员/分配器 |
    | 分配速度 | 移动栈指针，极快 | 查找空闲块，较慢 |
    | 大小 | 有限，Linux 默认 8MB | 受可用内存与碎片限制 |
    | 碎片 | 无 | 有外部/内部碎片 |
    | 生命周期 | 作用域结束即释放 | 手动或 RAII 释放 |

    栈溢出常见于深递归和超大局部数组，改堆分配或加 `-Wl,-z,stacksize` 只是治标。

???+ question "17. 局部 static 变量存在哪个区？什么时候初始化？"
    存在全局/静态区（`.data` 或 `.bss`），不在栈上，程序启动时分配空间、首次执行到定义处才初始化。
    C++11 起初始化是线程安全的：编译器生成 guard 变量 + `__cxa_guard_acquire/release`，多线程只会初始化一次（C++11 前需手写双检锁或 `pthread_once`）。

???+ question "18. 内存对齐是什么？struct 的大小怎么算？"
    成员按自身对齐数（通常是 `min(sizeof(T), 最大对齐)`）放在能被整除的偏移上，struct 总大小补齐到最大对齐数的整数倍。
    例：`struct { char a; int b; char c; }` 在 x86-64 上是 12（a@0，b@4，c@8，补到 12）。
    可用 `#pragma pack` 或 `alignas` 调整，但会牺牲访问性能甚至触发总线错误（严格对齐平台）。

???+ question "19. sizeof 一个空类是多少？含虚函数的类呢？"
    空类 `sizeof` 为 1：标准要求同类型不同对象地址不同，编译器塞一个占位字节。
    含虚函数的类多一个 `vptr`，x86-64 上是 8 字节；再加成员还要算对齐。
    注意 `sizeof` 是编译期常量（VLA 等扩展除外），不会求值表达式。

???+ question "20. sizeof 和 strlen 有什么区别？"
    `sizeof` 是运算符，编译期得到字节数，数组得整个数组大小，`char buf[10]` 得 10；`strlen` 是函数，运行期数到 `'\0'`，不含结尾符。
    指针用 `sizeof` 得到指针大小（8），不是所指内容大小。
    数组作为函数参数会退化为指针，此时 `sizeof` 得到 8，这是经典坑。

???+ question "21. 数组名和指针是什么关系？"
    数组名在大多数表达式里退化为首元素指针（`arr` → `&arr[0]`），所以能 `arr[i]`、能传给 `T*` 形参。
    但 `sizeof(arr)`、`&arr`、`typeid(arr)` 不退化：`&arr` 的类型是 `T(*)[N]`，加一就跳过整个数组。
    数组不是指针：没有「数组的引用计数」，不能用 `arr = p` 赋值。

???+ question "22. const 指针的三种写法怎么区分？"
    | 写法 | 含义 | 能否改指向 | 能否改内容 |
    | --- | --- | --- | --- |
    | `const int* p` | 指向常量的指针 | 能 | 不能 |
    | `int* const p` | 指针常量 | 不能 | 能 |
    | `const int* const p` | 两者都不能改 | 不能 | 不能 |

    口诀：`const` 在 `*` 左边修饰「指向的对象」，在 `*` 右边修饰「指针本身」；从右往左读最稳。

???+ question "23. 内存泄漏的常见原因和排查手段有哪些？"
    原因：`new` 后忘记 `delete`、异常/提前 `return` 跳过释放、`shared_ptr` 循环引用、容器里存裸指针未释放、`new[]` 用 `delete`。
    排查：AddressSanitizer（`-fsanitize=address`）、Valgrind、Windows 的 `_CrtDumpMemoryLeaks`、自己重载 `operator new/delete` 计数。
    根治靠 RAII：资源交给智能指针和容器，析构即释放。

???+ question "24. 段错误（segmentation fault）的常见原因？"
    解引用空指针或野指针、数组/容器越界写、栈溢出（深递归、巨大局部数组）、写只读区（字符串字面量）、重复 `free` 或释放非堆地址。
    定位：开 core dump 用 gdb `bt` 看栈，或用 ASan 直接给出越界行号；`-g -O0` 保留符号。
    注意越界读常常不立刻崩，等崩的时候现场已经离案发地很远。

???+ question "25. malloc 的底层是怎么实现的？brk 和 mmap 分别什么时候用？"
    glibc 的 `malloc` 维护 arena 和 bins（tcache、fastbin、smallbin、largebin、unsorted bin）复用空闲块。
    小块通过 `brk/sbrk` 抬高 program break 扩展堆；大于 `MMAP_THRESHOLD`（默认 128KB）的请求用 `mmap` 匿名映射，`free` 时 `munmap` 直接还给系统。
    多线程各有 arena 减少锁竞争，这也是「free 后内存没还给 OS」的常见原因。

## 三、类与对象

???+ question "26. 构造函数和析构函数的调用顺序是怎样的？"
    构造：虚基类 → 普通基类（按继承列表）→ 成员（按声明顺序，与初始化列表顺序无关）→ 自身构造体。
    析构：自身析构体 → 成员逆序 → 基类逆序，虚基类最后。
    成员按声明顺序初始化是高频坑，`-Wreorder` 能提前报警。

???+ question "27. 为什么用初始化列表？它和构造函数体内赋值有什么区别？"
    初始化列表直接调用成员的构造函数；函数体内赋值是先默认构造再赋值，多一次操作，对 `const`、引用和无默认构造的成员甚至无法通过编译。
    初始化顺序由声明顺序决定，初始化列表的书写顺序不影响，写错顺序读到未初始化值是 UB。
    成员里有大对象时，列表初始化能省一次构造 + 析构。

???+ question "28. 拷贝构造函数什么时候被调用？参数为什么必须是引用？"
    调用时机：用同类型对象初始化新对象（`T b = a;`、`T b(a);`）、按值传参、按值返回（未被 RVO 消除时）、容器插入与扩容。
    参数若按值传递，传参本身要调用拷贝构造，会无限递归，编译器直接报错。
    标准写法 `T(const T&)`，加 `const` 才能绑定临时对象；C++11 起还要配 `T(T&&)`。

???+ question "29. 深拷贝和浅拷贝有什么区别？"
    默认拷贝构造/赋值是逐成员拷贝：指针成员只复制地址，两个对象指向同一块内存，即浅拷贝。
    一方析构后另一方悬空，或双方各 `delete` 一次导致 double free，因此持有资源时必须深拷贝。
    现代做法：用 `std::string`、`std::vector`、`unique_ptr` 等 RAII 成员，让默认拷贝自动正确（Rule of 0）。

???+ question "30. 赋值运算符重载要注意什么？"
    返回 `T&` 以支持链式赋值并避免多余拷贝；参数用 `const T&`；必须先处理自赋值。
    要保证异常安全：先申请新资源、成功后再释放旧资源，或用 copy-and-swap。
    不要忘了 `if (this == &other) return *this;`，以及 C++11 补上移动赋值。

???+ question "31. Rule of 3 / 5 / 0 分别是什么？"
    Rule of 3：需要自定义析构、拷贝构造、拷贝赋值中的任何一个，通常三个都要写。
    Rule of 5：C++11 再加移动构造与移动赋值，且移动操作要标 `noexcept`。
    Rule of 0：用 RAII 成员管理资源，不写任何特殊成员函数，交给编译器生成，最不易错。

???+ question "32. explicit 有什么用？"
    阻止单参构造函数的隐式转换：`explicit Box(int)` 后 `Box b = 10;` 编译失败，必须 `Box b(10);`。
    也阻止函数传参、容器初始化等场景的隐式转换链，避免「莫名其妙就能编译」。
    经验：单参构造默认加 `explicit`，只有确实想要隐式转换（如 `string` 接受 `const char*`）才不加；C++11 起转换运算符也能 `explicit`。

???+ question "33. 友元（friend）有什么特性？"
    友元函数/类可以访问 private/protected 成员；友元不是成员函数，没有 `this`，也不能被继承。
    关系是单向的、不传递的：A 是 B 的友元，不代表 B 能访问 A，也不代表 A 的子类能访问 B。
    典型用途是 `operator<<`、`operator>>` 和需要紧密协作的两个类。

???+ question "34. static 成员变量和 static 成员函数有什么特点？"
    静态数据成员属于类而非对象，所有对象共享一份，`sizeof` 不计入对象；C++17 之前必须类外定义，之后可 `inline static` 类内定义。
    静态成员函数没有 `this`，不能访问非静态成员，也不能是 `const`/`virtual`。
    常用来做工厂方法、单例入口、全局配置。

???+ question "35. const 成员函数有什么意义？"
    承诺不修改对象状态（`mutable` 成员除外），因此 const 对象和 const 引用只能调用 const 成员函数。
    可以重载：同时提供 `T& get()` 与 `const T& get() const`，按对象 const 性选择。
    它也是接口契约的一部分，成员函数能加 const 就加。

???+ question "36. mutable 关键字有什么用？"
    允许在 const 成员函数中修改该成员，用来表达「逻辑常量、物理可变」。
    典型场景：缓存计算结果、`mutable std::mutex`（`lock()` 是非 const 的）、访问计数、懒加载。
    滥用会破坏 const 语义，只应该放不影响对象可见状态的辅助数据。

???+ question "37. this 指针是什么？有什么用途？"
    `this` 是隐含在非静态成员函数里的指针，指向当前对象；`const` 成员函数中类型是 `const T* const`。
    用途：区分同名成员与参数、返回 `*this` 支持链式调用、在成员函数里把自身传给外部、判断是否同一对象。
    构造函数里 `this` 可用但对象尚未完整构造，不要在其中调用虚函数或把 `this` 交出去。

???+ question "38. 返回 *this 的值和引用有什么区别？"
    返回 `T`：拷贝一份新对象，对返回值修改不影响原对象，链式调用会断在临时对象上。
    返回 `T&`：返回自身，支持 `a = b = c`、`s.append("a").append("b")` 这类链式修改。
    赋值运算符、复合赋值、流式接口都应返回 `T&`。

???+ question "39. 什么是对象切片（object slicing）？"
    派生类对象按值赋给基类对象时，只拷贝基类子对象，派生部分被「切掉」，此后调用虚函数也只剩基类行为。
    原因是按值拷贝只按静态类型 `Base` 的布局复制，没有多态。
    规避：用 `Base&`/`Base*` 传参、容器存 `unique_ptr<Base>`、把基类拷贝构造设为 `protected` 或 `= delete`。

???+ question "40. 如何禁止一个类被拷贝？如何禁止在栈上创建？"
    禁止拷贝：C++11 写 `T(const T&) = delete; T& operator=(const T&) = delete;`；C++98 声明为 private 且不实现。
    禁止栈上：把析构函数设为 private/protected，或 `~T() = delete`，再用静态工厂返回指针（需自定义删除器）。
    禁止堆上：`void* operator new(std::size_t) = delete;`，同时删 `new[]` 与 placement new。

## 四、继承与多态

???+ question "41. 面向对象的三大特性是什么？"
    封装：隐藏实现细节，只暴露稳定接口，降低耦合。
    继承：复用并扩展已有类型，表达 is-a 关系；组合表达 has-a，通常优先组合。
    多态：同一接口不同实现，编译期由重载/模板实现，运行期由虚函数 + vtable 实现。

???+ question "42. 虚函数的实现原理是什么？vtable 和 vptr 是什么？"
    每个含虚函数的类由编译器生成一张虚函数表 vtable（函数指针数组），每个对象内含一个 vptr 指向它。
    调用 `p->f()` 时先取 vptr，再按固定偏移取函数指针并间接调用，因此运行期才知道实际类型。
    vtable 每个类一份、放在只读数据段；vptr 每个对象一份，在构造/析构过程中被改写。

???+ question "43. 虚表放在哪里？什么时候生成？vptr 什么时候设置？"
    vtable 在编译期生成，存放在只读数据段（`.rodata`），同类所有对象共享同一张表。
    vptr 在构造函数里写入：基类构造时指向基类表，进入派生类构造体后改指派生类表；析构时反向改回。
    因此构造/析构期间调用虚函数不会分发到尚未构造或已经销毁的派生类。

???+ question "44. 为什么基类析构函数通常要声明为 virtual？"
    通过基类指针 `delete` 派生对象时，若析构非虚，只调用基类析构，派生类资源泄漏，且标准上属于 UB。
    声明为 `virtual ~Base()` 后，删除时经 vtable 调到最派生类析构再逐层向上，因此只要可能被继承并通过基类指针删除，析构就该虚。

???+ question "45. 构造函数和析构函数中调用虚函数会发生什么？"
    构造期间 vptr 被设为当前正在构造的类，调用的是当前类版本，不会分发到派生类；析构期间同理。
    这是有意为之：此时派生类成员还没构造或已经销毁，分发过去会访问未初始化/已释放的对象。
    所以「构造/析构里不要调虚函数」的真正含义是别指望多态。

???+ question "46. 纯虚函数和抽象类是什么？纯虚析构有什么特别？"
    `virtual void f() = 0;` 声明纯虚函数，含纯虚函数的类不能实例化，即抽象类。
    纯虚函数可以给实现（类外定义），派生类可用 `Base::f()` 显式调用；派生类未覆盖全部纯虚函数仍是抽象类。
    纯虚析构必须提供定义，否则派生类析构调用它时链接失败。

???+ question "47. 多重继承会带来什么问题？菱形继承怎么解决？"
    多继承让对象含多个基类子对象，可能有多个 vptr，指针转换需要 this 调整；同名成员产生二义性，需要限定符。
    菱形继承（B、C 继承 A，D 继承 B、C）会让 D 中含两份 A，访问 A 的成员二义且状态重复。
    解法是虚继承 `class B : virtual public A`，保证最派生类只保留一份 A 子对象。

???+ question "48. 虚继承是怎么实现的？有什么代价？"
    虚基类子对象只有一份，由最派生类负责初始化，中间类构造函数里的虚基类初始化会被忽略。
    实现上通过虚基类表（vbptr / vtordisp）或偏移量在运行时定位虚基类子对象，访问要额外间接寻址。
    代价是对象更大、构造更复杂、访问更慢，能不用就不用，优先组合。

???+ question "49. override 和 final 有什么用？"
    `override` 让编译器检查确实覆盖了基类虚函数，签名不一致（漏 const、参数类型不同）会直接报错，避免写成隐藏。
    `final` 修饰虚函数禁止继续覆盖，修饰类禁止被继承，可帮助编译器去虚化（devirtualization）。
    两者都是 C++11 的上下文关键字，写在函数或类名之后。

???+ question "50. RTTI 是什么？dynamic_cast 的原理和开销？"
    RTTI（运行时类型信息）包含 `typeid` 和 `dynamic_cast`，vtable 中保存指向 `type_info` 的指针。
    `dynamic_cast` 沿继承图检查目标类型，下行或交叉转换失败时指针返回 `nullptr`、引用抛 `std::bad_cast`。
    要求源类型是多态类型（有虚函数），开销来自运行期类型比较，比 `static_cast` 贵；能用访问者模式或标签替代就别用。

???+ question "51. 哪些函数不能声明为虚函数？"
    静态成员函数（无 `this`、不依赖对象）、构造函数（对象与 vptr 尚未建立）、友元函数（不是成员）。
    模板成员函数不能是虚函数（虚表大小需在类定义时确定）；`inline` 函数可以虚，但通过基类指针调用时通常无法内联展开。
    析构函数可以是且常常应该是虚函数。

???+ question "52. 多态有哪些实现方式？编译期和运行期分别指什么？"
    运行期多态：虚函数 + vtable + 基类指针/引用，代价是一次间接调用与无法内联。
    编译期多态：函数重载、模板、CRTP，静态绑定、可内联、零运行时开销，代价是代码膨胀与报错难读。
    工程上优先编译期多态，需要异构容器或插件式扩展时才用虚函数。

## 五、STL

???+ question "53. vector 的底层结构是什么？扩容机制是怎样的？"
    三根指针（`begin/end/cap`）指向一段连续堆内存，`size()` 是元素数，`capacity()` 是可容纳数。
    空间不足时申请新块（libstdc++ 2 倍、MSVC 1.5 倍），把元素移动或拷贝过去，再释放旧块。
    均摊插入复杂度 O(1)；扩容会让所有迭代器、指针、引用失效，知道规模时先 `reserve`。

???+ question "54. size 和 capacity 有什么区别？reserve 和 resize 呢？"
    `size` 是真实元素个数，`capacity` 是已分配空间能放多少；`size <= capacity`。
    `reserve(n)` 只保证容量至少 n，不改变 size、不构造元素；`resize(n)` 改变 size，多出的元素值初始化，少的析构。
    `shrink_to_fit()` 只是请求收缩，标准不保证真的归还内存。

???+ question "55. 各容器的迭代器什么时候失效？"
    vector：扩容时全部失效；`insert/erase` 使插入/删除点及之后失效。
    deque：中间插入删除全部失效，首尾插入使迭代器失效但引用/指针仍有效。
    list/map/set/unordered_*：只有被删除元素的迭代器失效；unordered 容器 rehash 会让全部迭代器失效。

???+ question "56. vector、list、deque 怎么选？"
    | 容器 | 内存 | 随机访问 | 中间插入 | 尾部插入 | 迭代器失效 |
    | --- | --- | --- | --- | --- | --- |
    | vector | 连续 | O(1) | O(n) | 均摊 O(1) | 扩容全失效 |
    | list | 链表 | 不支持 | O(1) | O(1) | 仅被删元素 |
    | deque | 分段连续 | O(1) | O(n) | O(1) | 中间操作全失效 |

    默认选 vector：缓存友好带来的常数优势通常大于复杂度劣势；只有频繁中间插入删除且元素大时才考虑 list。

???+ question "57. map 的底层是什么？为什么用红黑树而不是 AVL？"
    标准只要求平衡二叉搜索树，主流实现是红黑树：有序、查找/插入/删除 O(log n)、迭代器稳定。
    红黑树插入删除的旋转与重着色次数是常数级，AVL 更严格平衡、查询略快但维护成本高，STL 选了综合更稳的红黑树。
    节点额外存颜色和三个指针，内存开销明显大于 `vector`。

???+ question "58. map 和 unordered_map 怎么选？"
    `map`：有序、O(log n)、迭代器稳定、只需 `<`，适合范围查询与有序输出。
    `unordered_map`：哈希桶、平均 O(1)、最坏 O(n)、无序、需要 hash 与 `==`，rehash 会让迭代器失效，还可能有哈希洪水风险。
    对性能敏感且不要求顺序选 unordered_map，否则 map；极端场景可考虑开放寻址的自研哈希表。

???+ question "59. 哈希冲突有哪些解决办法？"
    链地址法：每个桶挂链表，冲突多时转红黑树（libstdc++ 阈值 8），删除简单、负载因子可大于 1。
    开放寻址：线性探测、二次探测、双重哈希、Robin Hood，缓存友好但删除要用墓碑标记，负载因子必须小于 1。
    工程上还要控制负载因子（默认 1.0 左右）及时 rehash。

???+ question "60. std::sort 的底层是什么？稳定吗？"
    introsort：快速排序为主，递归深度超过 `2*log2(n)` 时转堆排序保证 O(n log n) 最坏，小区间（≤16）用插入排序。
    C++11 起要求最坏 O(n log n)，所以不能是裸快排。需要稳定排序用 `stable_sort`（归并，可能额外分配）。
    对 `list` 用成员 `sort()`，对近似有序数据插入排序反而更快。

???+ question "61. string 的 SSO 是什么？"
    Small String Optimization：短字符串直接存在对象内部缓冲区，不分配堆内存。
    libstdc++ 的 `std::string` 是 32 字节，内部缓冲 15 字节；MSVC 也是 15（x64 下 15 或 22，取决于实现版本）。
    因此短字符串构造/拷贝/移动几乎无开销，长字符串才走堆；`sizeof(std::string)` 也远大于指针。

???+ question "62. priority_queue 的底层是什么？怎么建小顶堆？"
    底层是 `vector` + 堆算法（`push_heap/pop_heap/make_heap`），默认大顶堆，比较器是 `std::less`。
    `top()` O(1)，`push/pop` O(log n)，建堆 O(n)；不支持随机访问和遍历修改。
    小顶堆写 `priority_queue<int, vector<int>, greater<int>>`，自定义类型要提供严格弱序的比较器。

???+ question "63. STL 容器是线程安全的吗？"
    不是。多线程同时写同一个容器是数据竞争，即使写不同元素也没有标准保证（`vector<bool>` 尤其危险）。
    多线程只读同一容器是安全的；有写操作就必须外部加锁，或用无锁/分片结构自己保证。
    注意「const 成员函数可并发调用」也只在同一对象不被其他线程修改的前提下成立。

???+ question "64. 为什么 erase(remove(...)) 要写两段？"
    `std::remove` 只是把保留的元素前移，返回新的逻辑尾，容器 size 不变，尾部是待删除的残留值。
    必须再调用 `c.erase(new_end, c.end())` 真正缩短容器；否则尾部残留元素还在。
    C++20 可以直接 `std::erase(c, value)` / `std::erase_if(c, pred)`。

## 六、现代 C++

???+ question "65. 左值、右值、将亡值分别是什么？"
    左值（lvalue）有名字、可取地址、可出现在赋值左边；纯右值（prvalue）是字面量和临时计算结果。
    将亡值（xvalue）是「可以被移动」的对象，如 `std::move(x)` 的结果、返回右值引用的函数调用。
    左值 + 将亡值合称泛左值，纯右值 + 将亡值合称右值；右值引用 `T&&` 只能绑定右值。

???+ question "66. 右值引用解决什么问题？"
    让「临时对象」可以被识别，从而安全地窃取其内部资源而不是深拷贝。
    同时支持完美转发：`T&&` 在模板推导下成为万能引用，配合 `std::forward` 保留值类别。
    它本身只是类型，不延长生命周期（绑定到局部右值引用时临时对象生命周期会延长到引用作用域结束）。

???+ question "67. 移动语义的本质是什么？"
    移动构造/赋值把源对象的资源（堆指针、文件句柄）转移过来，并把源置为「有效但未指定」状态。
    典型实现是指针交换 + 源指针置空，复杂度 O(1)，不分配不拷贝。
    对 `vector` 扩容、函数返回大对象、容器存大对象收益最大；对 POD 类型移动等于拷贝。

???+ question "68. std::move 到底做了什么？"
    `std::move` 只是一个 `static_cast<T&&>`，把左值强制转成右值引用，本身不移动任何内存。
    真正的移动发生在随后调用的移动构造/移动赋值里；如果没有移动版本，会退化为拷贝。
    被 move 过的对象仍可析构和重新赋值，但不要读它的值。

???+ question "69. 什么是完美转发？为什么需要 std::forward？"
    模板参数 `T&&` 配合引用折叠，能原样接收左值和右值；转发给下层时必须用 `std::forward<T>(arg)` 保留值类别。
    如果直接按名字使用 `arg`，它永远是左值，右值属性丢失，下层只会走拷贝。
    `std::forward` 是条件转换：`T` 为左值引用时返回左值，否则返回右值引用。

???+ question "70. 三种智能指针分别适合什么场景？"
    `unique_ptr`：独占所有权，大小与裸指针相同，不可拷贝可移动，默认删除器零开销，首选。
    `shared_ptr`：共享所有权，引用计数原子操作，有控制块开销，适合生命周期不确定的共享资源。
    `weak_ptr`：不增加计数，用于观测 `shared_ptr`、打破循环引用、实现缓存。

???+ question "71. shared_ptr 的循环引用是怎么产生的？怎么解决？"
    两个对象互相持有对方的 `shared_ptr`，引用计数都至少为 1，离开作用域后也不会归零，对象与其资源永久泄漏。
    解决：其中一方改为 `weak_ptr`，使用时 `lock()` 提升为 `shared_ptr` 并判空。
    本质是「所有权成环」，设计时要明确谁拥有谁，非拥有关系一律 weak。

???+ question "72. make_shared 有什么优缺点？"
    优点：一次分配同时放下对象与控制块，少一次 `new`、缓存更友好、异常安全（不会出现对象已构造但控制块分配失败）。
    缺点：`weak_ptr` 还活着时整块内存（含对象）都不能释放，大对象 + 长寿命 weak 会拖内存；不能传自定义删除器。
    需要自定义删除器或从已有裸指针接管时用 `shared_ptr<T>(p, deleter)`。

???+ question "73. lambda 的捕获方式有哪些坑？"
    `[=]` 值捕获在创建时拷贝，默认 const（加 `mutable` 才能改副本）；`[&]` 引用捕获有悬空风险，尤其是异步/返回后使用。
    `[this]` 捕获指针，对象销毁后调用即 UB；C++17 可用 `[*this]` 拷贝整个对象。
    C++14 起支持初始化捕获 `[p = std::move(ptr)]`，用于把 `unique_ptr` 移进闭包。

???+ question "74. auto 和 decltype 的推导规则有什么不同？"
    `auto` 按值推导会丢掉引用和顶层 `const`，要保留需写 `auto&`、`const auto&`；`auto&&` 是转发引用。
    `decltype(expr)` 保留表达式的类型和值类别：`decltype(x)` 是变量声明类型，`decltype((x))` 是引用。
    `decltype(auto)` 用 `decltype` 规则推导返回值，适合完美转发返回类型。

## 七、编译与工程

???+ question "75. 从源码到可执行文件经历哪几个阶段？"
    预处理：展开宏、包含头文件、去注释、处理条件编译，产出 `.i`。
    编译：词法/语法/语义分析、优化，生成汇编 `.s`；汇编：生成目标文件 `.o`（含符号表与重定位信息）。
    链接：符号解析与重定位，合并段、解析库，产出可执行文件或共享库。

???+ question "76. 静态链接和动态链接有什么区别？"
    静态库（`.a`/`.lib`）在链接期把用到的目标代码复制进可执行文件：体积大、启动快、部署简单、无运行时依赖。
    动态库（`.so`/`.dll`）在加载或运行时解析：体积小、多进程共享、可独立升级，但要处理符号版本、`rpath`、ABI 兼容。
    动态库的符号默认全局可见，注意用 `-fvisibility=hidden` 控制导出。

???+ question "77. 头文件保护（include guards）为什么必要？"
    同一翻译单元中重复包含同一个头文件会导致类/模板/变量重复定义，编译报错。
    写法：`#ifndef X_H` / `#define X_H` / `#endif`，或 `#pragma once`（非标准但主流编译器都支持）。
    它防的是同一 TU 的重复包含，跨 TU 的重复定义要靠 `inline`、模板或 ODR 规则解决。

???+ question "78. inline 关键字到底有什么用？"
    语义作用：允许同一函数在多个翻译单元中定义而不违反 ODR，因此函数定义可以放头文件；C++17 的 `inline` 变量同理。
    优化作用：历史上建议编译器内联展开，现代编译器基本自行决定，`inline` 对优化只是提示。
    类内定义的成员函数隐含 `inline`；模板和 `constexpr` 函数也天然满足 ODR 豁免。

???+ question "79. 为什么模板不能像普通函数那样分离编译？"
    模板本身不是代码，只有被实例化才生成代码；编译器需要在看到调用点时拥有完整定义才能实例化。
    若定义放在 `.cpp` 里，其他翻译单元只见到声明，链接时找不到实例，报 undefined reference。
    解决：定义放头文件、显式实例化 `template class Foo<int>;`，或用 `.tpp/.ipp` 并在头文件末尾 `#include`。

???+ question "80. Debug 和 Release 构建有什么区别？为什么 Release 下会「莫名其妙」？"
    Debug 通常 `-O0 -g`、保留断言、变量不被优化，便于单步调试；Release 用 `-O2/-O3 -DNDEBUG`，会内联、重排、删除「无用」代码。
    行为差异大多来自未定义行为：越界、悬空指针、有符号溢出、未初始化变量，在 Debug 下凑巧正常，优化后暴露。
    排查手段：ASan/UBSan、`-fno-strict-aliasing`、`volatile` 调试变量，先消除 UB 再看优化。
